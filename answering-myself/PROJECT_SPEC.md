## 1. 서비스 한 줄 소개

하루에 하나씩 제시되는 정답 없는 질문에 방문자가 자신의 글을 남기고, 다른 사람의 글은 읽기만 할 수 있는 공개형 일기 공간.

## 2. 서비스 철학

- **기록 중심**: 일기를 쓰듯 자신의 생각을 기록한다.
- **하루 하나의 질문**: 동일한 날짜에는 단 하나의 질문을 제공한다.
- **비교·평가 없는 공간**: 글 사이의 상호작용, 경쟁 또는 소셜 반응을 유도하지 않는다.
- **오늘만 작성**: 지난 질문에는 새 글을 쓰거나 수정하여 참여할 수 없다.
- **과거는 읽기 전용**: 날짜를 찾아 이전 질문과 당시 작성된 기록을 열람한다.

## 3. 확정된 기능 요구사항

### 3.1 첫 진입 및 오늘의 질문
- 방문자는 첫 방문 시 **오늘 날짜의 질문** 화면으로 진입한다.
- 화면 상단: 날짜 및 질문 1개.
- 질문 아래: 오늘에 한해서 글쓰기 입력란과 `글 남기기` 버튼.
- 글쓰기 입력란 아래: 오늘의 글 목록.
- 질문은 하루에 **정확히 1개** 제공한다.
- 질문은 예측하기 어렵고 정답이 없는 개방형 질문으로 구성한다.
- 연속 질문이 비슷한 주제·사고 경로를 반복하지 않도록 기획한다.
- 질문 날짜는 **한국 표준시(KST) 오전 5시**에 전환하며 하루에 1개만 제공한다.
- 질문의 구체적인 생성 방식과 관리 주체는 미정이다.

### 3.2 글쓰기
- 방문자는 **오직 당일 질문에만** 글을 작성할 수 있다.
- 과거 질문으로 이동하면 글쓰기 입력란을 숨기고 읽기 전용 안내를 표시한다.
- 빈 글은 제출하지 않는다.
- **회원가입, 익명성 보장 방식, 글자 수 상한, 동일 사용자 중복 작성 제한, 수정·삭제 정책은 미정**이며 코덱스가 임의로 확정하지 않는다.
- 프로토타입에서는 구현 시험용으로 10,000자 입력 상한을 사용하지만 **제품 정책이 아니다**.
- 프로토타입의 `글 남기기` 버튼은 화면 내 임시 목록에만 글을 추가한다. 실제 저장 기능이 아니다.

### 3.3 글 목록
- 날짜별 질문에 달린 글을 최신순으로 나열한다.
- **한 페이지에 글 5개**만 보여준다.
- 글 본문은 **처음 200자만 미리보기**로 표시한다.
- 200자를 초과한 글에는 `전체 글 보기`를 제공하고, 펼친 글에는 `접기`를 제공한다.
- 200자 이하 글에는 펼치기 버튼을 표시하지 않는다.
- 페이지네이션은 `이전 / 현재 페이지 / 다음`을 기본으로 한다.
- 페이지 변경 시 이전에 펼친 상태를 초기화한다.
- 타인의 글에는 **댓글, 답글, 좋아요, 공감, 리액션, 평가, 공유 기반 상호작용을 제공하지 않는다.**
- 글 작성자 표시 방식은 미정. 프로토타입의 `익명의 글` 표시는 시연 목적이다.

### 3.4 날짜별 사이드메뉴
- 트리 구조: **연도(yyyy) → 월(mm) → 날짜(dd): 질문 내용**.
- 연도와 월은 기본 접힘 상태.
- **현재 선택한 날짜가 속한 연도/월은 위치 확인을 위해 자동 펼침**(추천 UX, 정책 결정 전 변경 가능).
- 날짜를 선택하면 해당 날짜의 질문과 글 목록으로 이동한다.
- 모바일에서는 사이드메뉴를 열고 닫는 방식으로 제공한다.
- 동일 날짜에 질문은 하나만 존재한다.

### 3.5 과거 질문
- 질문과 기존 작성글 조회 가능.
- **글 작성 불가**(확정 정책).
- 다른 사용자의 글에 어떤 상호작용도 불가.
- 과거 글의 보존 방식 및 아카이브·초기화는 아직 정하지 않는다.

## 4. 제외 기능 (개발 금지)

- 댓글, 답글, 스레드
- 좋아요, 공감, 싫어요, 이모지 반응
- 사용자 간 팔로우, 메시지, 알림, 멘션
- 랭킹, 인기글, 조회수 순위, 참여 경쟁 UI
- 과거 질문에 새 글 작성
- 유료 플랜·결제·광고 기능의 임의 추가
- 결정되지 않은 정책(로그인·작성 횟수·삭제 규정 등)의 무단 도입

```text

├── 헤더: 서비스명 / 사이드메뉴(모바일)

│   ├── 카드 1~5
│   │   ├── 작성 시각
│   │   ├── 본문 미리보기(최대 200자)
│   │   └── 펼치기 / 접기

            └── dd — 질문 제목 [클릭 시 이동]
```

## 7. 데이터 모델 초안 (구조 예시, 저장소 미선정)

```text
Question
  id: unique ID
  local_date: YYYY-MM-DD (KST 오전 5시를 날짜 전환 기준으로 사용)
  text: string
  published_at: timestamp
  // local_date UNIQUE

Entry
  id: unique ID
  question_id: Question ID
  body: string
  preview: first 200 characters (선택적 사전 계산)
  created_at: timestamp
  // 작성자 식별 / 수정·삭제·스팸 방지 필드는 정책 결정 후 확정
```

**중요:** 브라우저의 현지 날짜를 신뢰해 '오늘' 작성 가능 여부를 판단하지 않는다. 실서비스에서는 **KST 오전 5시**를 날짜 전환 기준으로 사용하고, 과거 날짜에 대한 제출을 API/DB 규칙에서 거부해야 한다.

## 8. 권장 조회·성능 방향 (기술 확정 아님)

- 목록을 한 번에 모두 가져오지 않고 5개씩 조회한다.
- 본문 200자 미리보기와 전체 본문은 필요할 때만 전송하는 설계를 검토한다.
- 펼친 본문은 세션 내 캐시 가능.
- 새 글 추가 중 목록 이동 시 중복·누락을 줄이도록 **커서 기반 페이지네이션**을 검토한다.
- 과거 메뉴 항목은 연도/월 단위 지연 로딩을 검토한다.
- 단, 현재 HTML 프로토타입은 실제 DB 없이 화면 동작만 시연한다.

## 9. 배포·운영의 현재 결정 범위

- 프런트엔드 배포 후보: **GitHub Pages**.
- GitHub Pages는 정적 호스팅이므로 방문자 작성글을 단독으로 저장할 수 없다.
- DB·API: **미정**, 무료/저비용 운영을 우선 고려.
- 글이 월 100개일 수도 월 10,000개 이상일 수도 있으므로 실제 사용량을 계측한 후 비용 판단.
- 아카이브, 데이터 초기화, 유료 서비스 사용 여부: **추후 결정**.
- 개인정보, 부적절한 게시글, 스팸 및 악성 요청 대응 방안: 실제 공개 전에 반드시 설계.
